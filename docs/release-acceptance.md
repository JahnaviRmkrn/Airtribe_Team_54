## Safe local gates

Use already-installed dependencies in a reviewed, **secret-excluded** source
checkout or disposable source snapshot. Do not copy credential directories,
local env files or cached deployment data into it. Do not print actual env
values. `env -i` strips inherited variables but does not stop tools such as Next
from loading files. The root test config's env-file isolation is not a substitute
for sanitizing inherited `process.env` or for the build preflight below.

Run from the repository root; this check inspects existence, not file contents:

```sh
set -e
for file in .env*; do
  [ "$file" = .env.example ] && continue
  if [ -e "$file" ] || [ -L "$file" ]; then
    echo 'Stop: use a source tree without local env files.' >&2
    exit 1
  fi
done
node_bin=$(command -v node)
clean_path="$(dirname "$node_bin"):/usr/bin:/bin"
env -i PATH="$clean_path" NODE_ENV=test TZ=UTC "$node_bin" \
  node_modules/vitest/vitest.mjs run --configLoader native --no-cache --maxWorkers=2
env -i PATH="$clean_path" NODE_ENV=test "$node_bin" \
  node_modules/typescript/bin/tsc --noEmit --incremental false
env -i PATH="$clean_path" NODE_ENV=test ./node_modules/.bin/eslint .
env -i PATH="$clean_path" NODE_ENV=test "$node_bin" scripts/check-repo.mjs
git diff --check
```

Use the installed ESLint shim: it supplies the dependency-resolution context.
The native config loader/no-cache options also support read-only dependency
stores. Do not install packages, run secret scripts or use GitHub authentication
inside application/test subprocesses just to make these checks run.

The additional harnesses are separate from the default test-file count. Their
configs use isolated env directories; all identities/data/provider responses
are synthetic and database migrations run **only in memory**, not on a service:

```sh
fixture() {
  config=$1; shift
  env -i PATH="$clean_path" NODE_ENV=test TZ=UTC "$@" "$node_bin" \
    node_modules/vitest/vitest.mjs run --config "$config" \
    --configLoader native --no-cache
}
fixture tests/local-room-harness/vitest.config.mjs TEAM54_LOCAL_HARNESS_MODE=smoke
fixture tests/local-organizer-harness/vitest.config.mjs TEAM54_ORGANIZER_HARNESS_MODE=smoke CONTACT_CREATE_RETRY_ENABLED=false
fixture tests/local-organizer-harness/vitest.config.mjs TEAM54_ORGANIZER_HARNESS_MODE=smoke CONTACT_CREATE_RETRY_ENABLED=true
fixture tests/local-google-harness/vitest.config.mjs
fixture tests/local-google-http-harness/vitest.config.mjs TEAM54_GOOGLE_HTTP_MODE=smoke
fixture tests/local-traction-harness/vitest.config.mjs TEAM54_TRACTION_HARNESS_MODE=smoke TRACTION_SINCE=2026-10-24T00:00:00Z TRACTION_TEST_DOMAINS=example.com TRACTION_TEAM_NAMES=FixtureTeam
./tests/local-auth-harness/run.sh smoke
./tests/local-auth-harness/run.sh proxy-smoke
```

Smoke modes close their listeners. For native browser checks, use each harness
README, one operator/server at a time, a frozen source hash and explicit cleanup.
Do not replace real handler success bodies just to obtain a passing browser.
The room smoke intentionally waits for the production 15-second timeout.
Traction's shipped unavailable state can be HTTP 200: inspect error content and
absence of success totals, rather than claiming a page-level 503.

After the same env-file preflight, a build in the disposable tree uses an empty
HOME and writes local build artifacts only:

```sh
(
  build_home=$(mktemp -d /tmp/team54-build-home.XXXXXX)
  trap 'rm -rf -- "$build_home"' EXIT
  env -i PATH="$clean_path" HOME="$build_home" NODE_ENV=production \
    NEXT_TELEMETRY_DISABLED=1 ./node_modules/.bin/next build --turbopack
)
```

## Release boundaries

Read [feature rollout](feature-rollout.md) before any live setup. This validation
did not apply live migrations, rotate credentials, enable optional features,
connect providers, send messages/invitations or charge payments. Code and a green
build do not satisfy those operator checks.

- [Bounded organizer reads](bounded-organizer-reads.md) and
  [traction limits](traction-read-limits.md) fail explicitly at finite budgets;
  neither is a transaction snapshot or unlimited-account promise.
- [Contact receipts](contact-create-retries.md) remain optional. Legacy unkeyed
  requests do not gain idempotency from tests of the keyed path.
- [Payment rollout](payment-safety-rollout.md) retains the old-writer/in-flight
  limitation; a new build cannot retroactively make previous provider requests safe.
- Google [Contacts](google-contacts-setup.md), [Sheets](google-sheets-setup.md) and
  [Gmail/Calendar](google-actions-setup.md) require separate approved readiness,
  grants and migrations. Unknown outcomes are not permission to resend.
- [Editable copy feedback](editable-draft-copy.md) does not cancel or undo an
  already-started clipboard write; edited text needs a later explicit activation.

The legacy `scripts/smoke.mjs` is **not** one of these gates: it loads environment
configuration and creates Auth/API/database records. It requires explicit
operator approval for a disposable target. Never run it against a deployment
merely to verify a release, nor weaken Auth settings to make it pass.
